# CLI contracts

Commands are registered in `assistant/cli/commands.py`. The handlers still
raise `NotImplementedError` after checking the command shape. This page is the
behavior those handlers must grow into. It does not add service methods.

`find`, `list`, `search`, `delete`, and `birthdays` take their arguments on
the command line. `add` and `update` ask for fields after the command.

An empty answer while editing keeps the value already stored. The word
`clear` removes an optional value. `name` and `title` are required: `clear`
is rejected for them, and an empty answer while editing keeps the current
text.

Dates are `YYYY-MM-DD`. Phone and email format checks are
`is_valid_phone` and `is_valid_email`. Until those functions exist, the CLI
still collects the text and the contact service rejects a value the validator
rejects.

## Contacts

```text
add-contact
list-contacts
find-contact <id>
search-contacts <query>
update-contact <id>
delete-contact <id>
```

`add-contact` with a name uses that name. With no name, the first prompt asks
for it. The other fields are always prompted.

```text
> add-contact Ada Lovelace
Address (optional): London
Email (optional): ada@example.com
Birthday YYYY-MM-DD (optional): 1815-12-10
Phone (empty line to finish): +44 20 7946 0991
Phone (empty line to finish):
```

The service call is `add_contact(contact)` with a new `Contact`. Its `id` is
generated by the model. The scaffold usage is still `add-contact <name>`.
Issue #5 changes that usage text so a bare `add-contact` is valid.

`update-contact <id>` loads that contact and prompts once per field. The
current value is shown in brackets. Enter keeps it. `clear` is allowed for
address, email, birthday, and the phone list.

```text
> update-contact 6f1c2a90-1b2e-4d55-9a0c-7e8f6a5b4c3d
Name [Ada Lovelace]:
Address [London]: 12 St James's Square
Email [ada@example.com]: clear
Birthday [1815-12-10]:
Phones [+44 20 7946 0991] (empty line keeps the list, clear removes it):
Phone (empty line to finish):
```

A non-empty phone answer replaces the whole list. Further phone prompts
collect the replacement until an empty line. The service call is
`update_contact(contact)` with the same `id`.

`find-contact` prints the stored fields and the id. `list-contacts` prints one
contact per line as `<id>  <name>`. `search-contacts` uses the same line
format. `delete-contact` asks for no extra fields.

## Notes

```text
add-note
list-notes
find-note <id>
search-notes <query>
update-note <id>
delete-note <id>
```

`add-note` with a title uses that title. With no title, the first prompt asks
for it. Content is always prompted. Tags are not part of this flow. Issue #6
adds tag commands.

```text
> add-note Lecture
Content (empty line to finish):
Bring the notebook
Content (empty line to finish):
```

Content may be several lines. An empty line ends it. The service call is
`add_note(note)`.

`update-note <id>` prompts for title and content. Enter on the title keeps it.
Enter on the first content line keeps the stored content. `clear` on content
stores `""`.

```text
> update-note 2c0f1a4e-6b7d-4e5a-9c1d-0a1b2c3d4e5f
Title [Lecture]:
Content [Bring the notebook] (Enter keeps it, clear removes it):
Content (empty line to finish):
Bring the notebook
Also the slides
Content (empty line to finish):
```

The service call is `update_note(note)` with the same `id`.

## Birthdays

```text
birthdays
birthdays 14
```

With no number, the CLI calls `upcoming_birthdays(7)`. Otherwise it passes the
integer the user typed. A negative number is rejected before the service call.

## Bonus tags

These commands stay unimplemented until issue #6. They are not part of note
CRUD.

```text
add-tag <note-id> <tag>
remove-tag <note-id> <tag>
notes-by-tag <tag>
```

Filtering and sorting are part of #6 and do not have separate command names yet.
